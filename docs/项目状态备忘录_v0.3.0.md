## 二、v0.3.0 增量修复记录（2026-05-24）

### 2.1 切换对话卡顿（严重）
- **现象**: 切换对话时界面卡死，后台可见 /summarize 接口在跑
- **根因**: GET /conversations/{id}/summarize 直接调用 LLM 生成摘要，同步阻塞
- **修复**: 改为只读缓存，有则返回无则返回空，不触发LLM
- **文件**: `app/backend/routers/chat.py` 第530-538行

### 2.2 对话列表删除功能（新增）
- **需求**: 用户无法删除不需要的对话
- **实现**: 对话条目悬停显示删除按钮，确认后删除，当前对话自动清空
- **文件**: `frontend/src/views/Chat.vue`（模板+方法+样式）

### 2.3 长期记忆和对话摘要为空（严重）
- **现象**: 打开记忆面板，长期记忆和对话摘要都是空的
- **根因A**: 前端搜索关键词为空时直接返回空数组，没有调用 listLongTermMemory
- **修复A**: 关键词为空时调 listLongTermMemory() 展示全部记忆
- **根因B**: 摘要生成条件太苛刻（每20条才触发），大多数对话到不了20条
- **修复B**: 改为6条消息后即生成首次摘要，之后每20条更新
- **文件**: `frontend/src/views/Chat.vue`, `app/backend/routers/chat.py`

### 2.4 Chrome图标显示方框（体验）
- **现象**: Win7/Win10 Chrome中很多emoji显示为方框
- **根因**: Windows Chrome对部分emoji渲染支持有限
- **修复**: 安装 `@element-plus/icons-vue`，导航栏和关键按钮替换为矢量图标
- **文件**: `frontend/src/main.js`, `frontend/src/views/Chat.vue`, `frontend/src/App.vue`

### 2.5 输入框布局优化（体验）
- **需求**: 附件按钮不应和技能/记忆/进化并列，它是输入的一部分
- **修复**: 附件按钮移入输入框内部右下角，紧挨发送按钮；文本+附件+发送一体化
- **文件**: `frontend/src/views/Chat.vue`（模板重构+CSS重写）

### 2.6 AI不调工具直接从记忆回答（严重）
- **现象**: 用户问"搜一下文件"，AI直接从记忆里回答"你叫周博鑫"而不调用搜索工具
- **根因**: 系统提示太简单（"直接回答用户问题"），记忆注入提示太强（"你应该记住的上下文"）
- **修复**:
  - `data/system_prompt.json` 新增核心准则：涉及文件/数据操作必须用工具
  - skill_context 强调"必须调用工具，而不是纯文本猜测"
  - 记忆注入改为"仅供与当前问题相关时参考"
- **文件**: `data/system_prompt.json`, `app/backend/routers/chat.py`, `app/backend/core/memory.py`

### 2.7 后处理日志增强
- **修复**: 原来所有异常被 `except: pass` 吞掉，改为 `exc_info=True` 记录完整堆栈
- **文件**: `app/backend/routers/chat.py`（两处后处理函数）

## 三、关键技术决策记录

### 3.1 纯Python TF-IDF（不用numpy/sklearn）
- **决策**: 向量编码用纯Python实现TF-IDF
- **原因**: Win7离线环境无法安装numpy（CP扩展需MSVC编译）
- **代价**: 大量文件时性能不如numpy，但万级文件仍可接受
- **不可逆**: 如果要换numpy需要重新规划离线包依赖

### 3.2 Hybrid评分 0.7/0.3
- **决策**: `vec_score * 0.7 + kw_score * 0.3`
- **原因**: 语义匹配更重要，关键词作为补充纠偏
- **可调**: 后续可根据实际效果微调权重

### 3.3 三层技能可见性
- **决策**: visible / hidden / internal
- **原因**: 防止用户误关 read_file/write_file 等系统工具，同时不把这些工具展示给用户
- **不可逆**: internal级工具硬编码不可关闭

### 3.4 pythonw.exe 隐藏黑框
- **决策**: 用 pythonw.exe 替代 python.exe 启动后端
- **原因**: 用户误关CMD窗口会导致服务停止
- **注意**: pythonw无边框，异常信息看不到，需要看日志文件

### 3.5 对话摘要持久化
- **决策**: 生成的摘要永久存入SQLite，GET接口只读缓存
- **原因**: 切换对话时应秒回不能用LLM生成，摘要只用生成一次
- **策略**: 6条消息首次生成，每20条更新

### 3.6 记忆注入提示措辞
- **决策**: "仅供与当前问题相关时参考"（而非"你应该记住的上下文"）
- **原因**: 后者导致LLM偏向从记忆抄答案而不调用工具
- **教训**: 提示工程的微小措辞差异会产生巨大行为差异

## 五、离线包同步规则（重要！）

项目适配三个运行环境：开发机（Linux）、Win10离线、Win7离线。

### 同步要点
1. 代码变更后，把 `app/backend/` 下改过的文件同步到两个包的 `aide/app/backend/`
2. 前端变更后，先 `npm run build`，再把 `static/` 同步到两个包
3. `config/`、`docs/`、`data/` 变更也要同步
4. Win7包无 `desktop/` 目录（PySide6不支持Win7）
5. Win7包用cp38的whl，Win10用cp312的whl
6. 每次同步后跑MD5校验确认一致

### 离线包路径
- Win10: `/home/ubuntu/aide-win10-offline/aide/`
- Win7: `/home/ubuntu/aide-win7-offline/aide/`

### 快速同步命令
```bash
SRC=/home/ubuntu/.openclaw/workspace/ai-assistant
# 同步后端
cp $SRC/app/backend/routers/chat.py /home/ubuntu/aide-win10-offline/aide/app/backend/routers/chat.py
cp $SRC/app/backend/routers/chat.py /home/ubuntu/aide-win7-offline/aide/app/backend/routers/chat.py
# 同步前端
cp -r $SRC/app/backend/static/* /home/ubuntu/aide-win10-offline/aide/app/backend/static/
cp -r $SRC/app/backend/static/* /home/ubuntu/aide-win7-offline/aide/app/backend/static/
```
