> 日期：2026-05-21 | 基于产品定位调整：纯本地个人助手，开发者预配，用户开箱即用
>

## 产品定位确认

**AIDE = 纯本地个人AI助手**

- 安装在个人Windows电脑上，一人一份
- 数据全在本地，隐私天然保障
- 开发者预配好LLM、数据库、OA等连接信息，打包分发
- 用户拿到就能用，升级时数据不动只更代码和配置

## P0-1: 目录结构重组 — 数据与代码分离

### 为什么这是第一优先级

当前代码、配置、数据混在一起，升级时容易误删用户数据。**目录分离做不好，后面的升级机制就是空中楼阁。**

### 现状问题

```
backend/
  ├── .env                  ← 配置（升级要覆盖）
  ├── config/settings.py    ← 代码（升级要覆盖）
  ├── data/                 ← 用户数据（升级不能碰）
  │   ├── assistant.db
  │   ├── memory.db
  │   └── knowledge.db
  ├── output/               ← 用户文档（升级不能碰）
  ├── tasks/                ← 用户的定时任务（升级不能碰）
  ├── templates/            ← 文档模板（升级要覆盖+保留用户自建）
  └── ...
```

问题：`.env`和用户数据都在`backend/`下面，升级时很难精确控制哪些覆盖、哪些保留。

### 目标目录结构

```
aide/
  │
  ├── app/                        ← 📦 应用程序（升级时整体覆盖）
  │   ├── backend/
  │   │   ├── main.py
  │   │   ├── config/
  │   │   ├── core/
  │   │   ├── engines/
  │   │   ├── models/
  │   │   ├── renderers/
  │   │   ├── routers/
  │   │   ├── static/            ← 前端构建产物
  │   │   └── requirements.txt
  │   ├── frontend/               ← 前端源码（构建用，用户不碰）
  │   ├── desktop/                ← 桌面客户端代码
  │   └── venv/                   ← Python虚拟环境
  │
  ├── config/                     ← ⚙️ 预置配置（升级时覆盖，开发者维护）
  │   ├── default.env             ← 默认配置（LLM地址、数据库连接等）
  │   ├── db_schema.yaml          ← 数据库Schema定义
  │   ├── prompts.yaml            ← Prompt模板
  │   └── notifiers.yaml          ← 通知渠道配置
  │
  ├── data/                       ← 💾 用户数据（升级绝对不碰！）
  │   ├── assistant.db            ← 主数据库
  │   ├── memory.db               ← 记忆数据库
  │   ├── knowledge.db            ← 知识库数据库
  │   ├── knowledge_files/        ← 知识库文件
  │   ├── skills/                 ← 用户自定义技能
  │   └── system_prompt.json      ← 进化系统prompt（用户调过的）
  │
  ├── user/                       ← 👤 用户自定义配置（升级不碰）
  │   ├── user.env                ← 用户自己改的配置（优先级高于config/）
  │   ├── tasks/                  ← 用户的定时任务YAML
  │   └── templates/              ← 用户自建的文档模板
  │
  ├── output/                     ← 📄 用户生成的文档（升级不碰）
  │   └── reports/
  │
  ├── python/                     ← 🐍 嵌入式Python运行时
  │   └── python-3.8.10-embed-amd64/
  │
  ├── logs/                       ← 📋 运行日志
  │
  ├── start.bat                   ← 启动脚本
  ├── stop.bat                    ← 停止脚本
  ├── upgrade.exe                 ← 升级程序
  └── VERSION                     ← 当前版本号
```

### 配置加载优先级

```
启动时读取配置的顺序：

1. user/user.env          ← 用户自己改的，最高优先级
2. config/default.env     ← 开发者预置的默认配置
3. app/backend/config/settings.py  ← 代码中的硬编码默认值

如果 user/user.env 不存在，就用 config/default.env。
用户通过设置界面改配置时，写入 user/user.env，不碰 config/。
```

这样开发者升级时覆盖 `config/default.env` 推新配置，用户自己改过的 `user/user.env` 不受影响。

### 文档模板的合并策略

```
templates/ 目录拆分：

config/templates/     ← 系统内置模板（升级时覆盖）
user/templates/       ← 用户自建模板（升级不碰）

启动时合并两个目录，用户看到的是 系统模板 + 自己的模板。
同名模板以 user/ 下的为准（用户覆盖系统默认）。
```

## P0-2: 开箱即用 + 自动升级

### 核心理念

**你配好，他只管用。升级就像手机APP更新一样简单。**

### 2.1 安装：开箱即用

**开发者打包时（你做）：**

```
1. 把所有配置写进 config/default.env
   - LLM地址、模型名
   - 达梦数据库连接
   - OA接口地址
   - 邮件SMTP信息
   - 全部配好

2. 运行 build_offline.sh 生成安装包
   - 包内已含嵌入式Python
   - 包内已含配置好的 default.env
   - 包内已含前端构建产物

3. 分发安装包给用户
```

**用户安装（他做）：**

```
1. 双击 install.bat
2. 等进度条跑完（自动解压Python、安装依赖）
3. 双击 start.bat
4. 浏览器自动打开 → 看到欢迎引导页
5. 完事

全程不需要改任何配置文件！
```

### 2.3 自动升级机制

**架构设计：**

```
┌──────────────┐         ┌──────────────┐
│  内网升级服务器 │ ←─────→ │  用户电脑     │
│  (你维护)     │         │  AIDE        │
│              │         │              │
│  /updates/   │         │  upgrade.exe │
│    v0.2/     │         │  VERSION     │
│    v0.3/     │         │              │
│  manifest.json│        └──────────────┘
└──────────────┘
```

**升级服务器文件结构：**

```
内网HTTP服务器 /var/www/aide-updates/
  ├── manifest.json              ← 版本清单
  ├── v0.3/
  │   ├── aide-v0.3-update.zip   ← 增量更新包
  │   └── checksum.md5           ← 校验文件
  └── v0.4/
      ├── aide-v0.4-update.zip
      └── checksum.md5
```

**manifest.json 示例：**

```json
{
  "latest_version": "0.4.0",
  "min_upgrade_from": "0.2.0",
  "release_notes": "新增：自然语言查数据、文档模板系统、语音输入",
  "updates": [
    {
      "version": "0.4.0",
      "file": "v0.4/aide-v0.4-update.zip",
      "size": 52428800,
      "checksum": "abc123...",
      "release_date": "2026-06-15",
      "release_notes": [
        "新增自然语言数据查询功能",
        "新增文档模板系统，内置8个常用模板",
        "新增语音输入支持",
        "修复：文档生成偶尔格式错乱的问题"
      ],
      "breaking_changes": [],
      "config_updates": {
        "new_keys": ["VOICE_ENABLED", "TEMPLATE_DIR"],
        "changed_keys": {"LLM_MAX_TOKENS": "8192"}
      }
    }
  ]
}
```

**升级流程：**

```
用户电脑（自动或手动触发）：

1. 检查更新
   upgrade.exe → GET http://升级服务器/manifest.json
   对比本地 VERSION 文件
   
2. 发现新版本
   弹窗提示：
   ┌─────────────────────────────────────┐
   │  🆕 发现新版本 v0.4.0                │
   │                                     │
   │  新功能：                            │
   │  • 自然语言数据查询                   │
   │  • 文档模板系统                       │
   │  • 语音输入                           │
   │                                     │
   │  [立即更新]  [稍后提醒]  [跳过此版本]  │
   └─────────────────────────────────────┘

3. 下载更新包
   进度条显示下载进度
   下载完成后校验checksum

4. 执行升级
   ① 停止后端服务
   ② 备份当前 app/ 目录 → app_backup_v0.3/
   ③ 解压更新包，覆盖 app/ 和 config/
   ④ 不碰 data/、user/、output/ 目录
   ⑤ 合并新配置项到 config/default.env
      （如果用户改过该项，不覆盖，只记录提示）
   ⑥ 更新 VERSION 文件
   ⑦ 执行数据库迁移（如有新表/新字段）
   ⑧ 重启后端服务

5. 升级完成
   ┌─────────────────────────────────────┐
   │  ✅ 升级完成！已更新至 v0.4.0         │
   │                                     │
   │  ⚠️ 有2项配置变更，你之前自定义过，   │
   │  已保留你的设置，新默认值如下：        │
   │  • LLM_MAX_TOKENS: 你的=4096, 新默认=8192 │
   │                                     │
   │  [查看变更]  [知道了]                 │
   └─────────────────────────────────────┘
```

**更新包内容：**

增量更新包只包含需要覆盖的文件：

```
aide-v0.4-update.zip
  ├── app/                  ← 覆盖应用代码
  │   └── backend/
  │       ├── core/         ← 新增/修改的代码
  │       ├── engines/
  │       └── routers/
  ├── config/               ← 覆盖预置配置
  │   ├── default.env       ← 更新后的默认配置
  │   └── db_schema.yaml
  ├── upgrade_script.py     ← 升级脚本（数据库迁移等）
  └── UPGRADE.md            ← 升级说明
```

**升级安全机制：**

| 机制 | 说明 |
|------|------|
| 自动备份 | 升级前自动备份当前 `app/` 为 `app_backup_v版本号/` |
| 校验和 | 下载后校验MD5，防止包损坏 |
| 回滚 | 升级失败自动回滚到备份版本 |
| 数据库迁移 | 升级脚本中包含ALTER TABLE等迁移语句，增量执行 |
| 配置合并 | 新配置项自动追加，用户改过的项不覆盖 |
| 灰度提示 | 先检查兼容性，不兼容的版本不让升级 |

### 2.4 离线升级方案

部分用户电脑可能无法访问升级服务器（完全隔离网络），支持手动升级：

```
1. 开发者下载 aide-v0.4-update.zip 拷到U盘
2. 用户把U盘插上，双击 upgrade.exe
3. 选择"从本地文件升级"
4. 选择U盘上的zip文件
5. 执行同样的升级流程
```

### 2.5 开发者工具：打更新包

提供 `build_update.sh` 脚本，自动对比版本差异生成增量包：

```bash

./build_update.sh --from v0.3 --to v0.4

# 自动执行：
# 1. git diff v0.3 v0.4 -- app/ config/
# 2. 只打包变更的文件
# 3. 生成 checksum
# 4. 更新 manifest.json
# 5. 产出 aide-v0.4-update.zip
```

## P0-4: 自然语言转SQL（Text2SQL）

### 问题

定时分析任务需要手写SQL，工厂文员不会写。

### 方案

#### 4.1 核心流程

```
用户输入自然语言
    "查一下本月故障率最高的5台设备"
        ↓
    ① 获取数据库Schema（表名、字段名、中文注释）
        ↓
    ② 构建Prompt（Schema + 用户问题 + 达梦方言适配）
        ↓
    ③ LLM生成SQL
        ↓
    ④ SQL安全检查（只允许SELECT）
        ↓
    ⑤ 执行SQL，返回结果
        ↓
    ⑥ LLM自然语言解读 + 网页表格展示
```

#### 4.2 Schema管理

管理员（你）预先注册数据库表结构，包含中文注释：

```yaml
# config/db_schema.yaml
tables:
  - name: "device_status"
    comment: "设备运行状态表"
    columns:
      - name: "device_name"
        type: "VARCHAR"
        comment: "设备名称"
      - name: "device_code"
        type: "VARCHAR"
        comment: "设备编号"
      - name: "run_hours"
        type: "DECIMAL"
        comment: "运行时长（小时）"
      - name: "fault_count"
        type: "INTEGER"
        comment: "故障次数"
      - name: "record_date"
        type: "DATE"
        comment: "记录日期"
      - name: "workshop"
        type: "VARCHAR"
        comment: "所属车间"

  - name: "maintenance_record"
    comment: "维修记录表"
    columns:
      - name: "device_code"
        type: "VARCHAR"
        comment: "设备编号"
      - name: "fault_type"
        type: "VARCHAR"
```

#### 4.4 SQL安全沙箱

```python
class SQLSafetyChecker:
    FORBIDDEN = ["INSERT","UPDATE","DELETE","DROP","CREATE","ALTER",
                 "TRUNCATE","EXEC","GRANT","REVOKE","INTO OUTFILE"]
    MAX_ROWS = 1000
    TIMEOUT = 30

    def check(self, sql: str) -> tuple[bool, str]:
        sql_upper = sql.upper().strip()
        if not sql_upper.startswith("SELECT"):
            return False, "只允许SELECT查询"
        for kw in self.FORBIDDEN:
            if kw in sql_upper:
                return False, f"禁止{kw}操作"
        return True, "OK"
```
